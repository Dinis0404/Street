## 1. 專案摘要（60 秒理解全案）

現有 repo 是一個完成的 three.js 場景：「富士山下的 7-Eleven 河口湖站東店」（純靜態、離線、無 build）。

本專案要把它升級為**臺北市信義區的整區街景復刻**：以台北 101 為原點、1 單位 = 1 公尺，可漫遊約 2.4 km × 2.0 km，核心商圈逐窗逐招牌還原，含晝夜、天氣、車流、行人、跨年煙火。河口湖場景保留為第二張地圖。

- 底圖資料來源：OpenStreetMap（一次性腳本抓取 → 轉成 JS 資料檔 → 手工校訂）。
- 還原驗收：與實景照片逐格比對（沿用河口湖店面的既有工作法）。

## 3. 技術鐵律（不可違反）

1. **純靜態**：不引入 build step、不引入 npm、不用 CDN。所有資源相對路徑，部署 Vercel/GitHub Pages 零設定。
2. **離線可玩**：three.js 與 addons 一律使用 `libs/` 內建版本。若需要新的 addon（如 `BufferGeometryUtils`），**只能複製 three.js r149 對應版本的原始碼檔案**到 `libs/addons/`，不可升級 three.js 版本。
3. **效能預算制**：任何新功能都受 `docs/規劃.md` §9 預算約束（桌機 ≤900 draw calls / 60 fps；手機 ≤350 / 30 fps）。以內建效能面板（T0.4）量測為準。
4. **招牌風格化**：所有連鎖店招牌、商標以「風格化仿製」呈現（配色構圖接近、字樣自創或通用化），不重製真實商標圖樣。
5. **參考照片只比對不取材**：`docs/refs/` 內照片僅供視覺比對，不得裁切作為貼圖使用。
6. **程式碼風格與現有檔案一致**：2 空格縮排、繁體中文註釋、工廠函式風格、CanvasTexture 程式生成貼圖。
7. **新檔案一律放進規劃 §6.2 的模組結構**，不得再往單一檔案堆程式碼。

### 3.1 three.js r149 API 陷阱表（新代碼最容易踩雷處）

本專案固定 three.js **r149**，與新版 API 不同。接手 AI 若訓練資料是較新的 three.js，**必須**使用下表左欄的 r149 寫法：

| 誤用（r152+ 寫法） | r149 正確寫法 |
| --- | --- |
| `renderer.outputColorSpace = THREE.SRGBColorSpace` | `renderer.outputEncoding = THREE.sRGBEncoding` |
| `THREE.ColorManagement.enabled = true` | `THREE.ColorManagement.legacyMode = false`（見 `js/util.js` 開頭） |
| `texture.colorSpace = THREE.SRGBColorSpace` | `texture.encoding = THREE.sRGBEncoding` |
| 自訂 shader 內 `#include <colorspace_fragment>` | `#include <encodings_fragment>`（見 `world.js` 富士山 shader） |
| `import { mergeGeometries } from 'three/addons/utils/BufferGeometryUtils.js'` | 未內建。用 `js/util.js` 的 `mergeGeoms`（僅合併 position+normal，**丟棄 UV**）；需要 UV 合併時，把 r149 的 `BufferGeometryUtils.js` 複製到 `libs/addons/utils/` |
| import map 路徑 `three/addons/...` | 本專案直接相對路徑 `../libs/addons/...`（見 `index.html` 與 `main.js`） |
| `useLegacyLights = false` / 光強度物理單位 | r149 預設 legacy 燈光；點光源強度沿用現有 `userData.base` 機制 |

### 3.2 內建資產清單（動工前盤點）

```
libs/three.module.js                        r149 核心
libs/addons/postprocessing/EffectComposer.js / RenderPass.js /
  ShaderPass.js / UnrealBloomPass.js / MaskPass.js / Pass.js
libs/addons/shaders/CopyShader.js / GammaCorrectionShader.js /
  LuminosityHighPassShader.js
```

沒有的：GLTFLoader、OrbitControls、BufferGeometryUtils、各種 Loader。需要時按鐵律 2 補 r149 版本檔案。

### 3.3 現有可複用的代碼模式（新代碼必須沿用）

| 模式 | 位置 | 說明 |
| --- | --- | --- |
| `makeCanvasTexture(w, h, draw)` | `js/util.js` | 一切貼圖的生成入口（sRGB、anisotropy 8 已設好） |
| `textTexture(text, bg, fg, w, h, size, vertical)` | `js/util.js` | 招牌文字貼圖（`vertical: true` 畫直式招牌） |
| `mergeGeoms(geoms)` | `js/util.js` | 同材質幾何合併（僅 position+normal） |
| `glowTexture()` / `softDotTexture()` / `cloudTexture()` | `js/util.js` | 光暈/粒子/雲 |
| `userData = { day, night }` 發光材質 | `js/world.js` | 晝夜 emissive 插值 → P0 抽成註冊表 |
| `A(mesh)` 加場景＋陰影、`addCol(x1,x2,z1,z2)` 碰撞 | `js/world.js` | P0 泛化為跨場景公用 |
| 中文字型鏈 | `js/util.js` | `"Microsoft JhengHei","PingFang TC",sans-serif` |

## 4. 工作流與 Git 規範

1. **分支**：直接在 `main` 開發（個人專案），遠端 `origin = https://github.com/Dinis0404/Fuji-7-Eleven.git`。
2. **commit 格式**：沿用現有風格 —— `feat: / refactor: / fix: / docs:` + 中文描述，一個任務一個 commit，例：
   ```
   feat: P0-T0.4 效能面板（FPS/draw calls/三角形數）
   ```
3. **階段完成**：打 tag（`phase-0`、`phase-1`…）→ `git push origin main --tags` → 更新 `start.md` 進度區。
4. **照片比對**：參考照片放 `docs/refs/<街區>/`；比對結果截圖命名 `compare-<比對點>.png` 放同目錄。比對不通過 → 修正 → 重比，**不通過不得進下一任務**。
5. **每個任務完成時**：同步更新 `start.md` 的「目前進度」勾選框與本文件 §5 狀態表。
6. **使用者的溝通語言**：繁體中文。每次回報需含：做了什麼、瀏覽器驗證結果、效能數據、下一步。

## 6. 階段任務書

> 每個任務格式：`編號` 名稱 — 做法 → **驗收**。做法寫的是「方向與要點」，實作細節由 AI 對照實景自行決定；驗收條件是硬門檻。

### P0 架構改造（地基，本階段程式碼量最大但不產出新場景）

**目標**：把單體式代碼拆成可承載整座城市的模組化架構，行為零變化。

- [ ] **T0.1 模組拆分**：`main.js` 拆為 `core/`（renderer、composer、input、ui、loop）；`environment.js` 拆為 `systems/daynight.js` + `systems/weather.js`；`world.js` 中可泛用的 helper（`A()`、`addCol`、canvas 貼圖樣板）抽到 `factory/`。**驗收**：河口湖場景所有控制項與視覺與拆分前一致，diff 只移動不改邏輯。
- [ ] **T0.2 場景註冊器**：`core/scenes.js` — `{ fuji: worldFactory, xinyi: placeholderFactory }`；`index.html` 加地圖選擇選單；URL 參數 `?scene=fuji` 直達。**驗收**：可切換地圖，placeholder 場景是灰盒＋「施工中」告示牌。
- [ ] **T0.3 夜間燈光註冊表**：`systems/nightlights.js` — `register(material, {day, night})`、`update(hour)` 全域插值；遷移 `glow.signMats / lampLights / lampGlows / windowMats`。**驗收**：河口湖夜景亮燈效果與現在完全相同。
- [ ] **T0.4 效能面板**：`core/stats.js` — FPS、draw calls（`renderer.info.render.calls`）、三角形數、JS heap（`performance.memory`，Chrome）；`F3` 切換；自動取 10 秒平均。**驗收**：顯示四項數據，河口湖場景桌機 60 fps。
- [ ] **T0.5 除錯相機**：`F` 鍵進出自由飛行（WASD＋Q/E 升降＋Shift 加速×4＋滑鼠轉向）。**驗收**：能飛進 7-11 簷板檢查貼圖。
- [ ] **T0.6 空間雜湊碰撞**：`core/spatialhash.js` — cell 20 m 的 `insert(aabb)` / `query(x, z)`；`character.js` 改查雜湊。**驗收**：河口湖所有碰撞行為不變（撞牆、跳上人行道），角色移動效能不低於改前。
- [ ] **T0.7 可走面系統**：`city/ground.js` — 區域多邊形（含高度）＋樓梯/坡道定義的 `surfaceHeightAt(x, z)`；遷移 `groundHeightAt` 全部硬編碼分支。**驗收**：棧橋、人行道行走高度正確。
- [ ] **T0.8 Instancing 基建**：`factory/geo.js` — `makeInstanced(geom, mat, transforms[])` 回傳 `THREE.InstancedMesh`（含 castShadow 選項）。**驗收**：把河口湖 5 根阻車柱改成 instanced，畫面無異。
- [ ] **T0.9 vendor BufferGeometryUtils**：複製 r149 的 `examples/jsm/utils/BufferGeometryUtils.js` 到 `libs/addons/utils/`，刪除其中對非內建模組的依賴（若有）。**驗收**：`mergeBufferGeometries` 可合併帶 UV 的幾何。
- [ ] **T0.10 chunk 串流基建**：`city/chunk.js` + `city/city.js` — 150 m 格、狀態機 `queued→building→active→dormant`、每幀建構預算 4 ms、距離優先佇列、dormant 時 dispose 幾何（材質快取保留）。以河口湖場景做 12 個假 chunk 接入測試。**驗收**：走動時 chunk 隨距離載入/休眠，效能面板無尖峰超過 16 ms 幀。

**P0 總驗收**：河口湖場景在新架構上功能全同、60 fps、無 console 錯誤；效能面板可隨時監看。完成後 commit + tag `phase-0`。

### P1 骨幹路網＋首批地標（第一次出現信義區場景）

**目標**：OSM 資料管線打通；全區道路＋街廓量體成形；101/市政府/四四南村三個 S 級地標完成；「南村望 101」構圖成立。

- [ ] **T1.1 資料管線**：`tools/build-district.mjs`（Node 一次性腳本，不隨遊戲發布）——Overpass API 抓取 bbox `25.0230,121.5528,25.0446,121.5766`（南,西,北,東）的 `building`（含 height/levels/name）與 `highway`（含 class/lanes/oneway），投影到世界座標，輸出 `js/data/district.js`（格式見 §8）。投影公式：
  ```
  x = (lon − 121.5647) × 100980     # 向東為正
  z = −(lat − 25.0338) × 111320     # 向北為負（-z 北）
  ```
  Overpass 查詢骨架：
  ```
  [out:json][timeout:120];
  ( way["building"](25.0230,121.5528,25.0446,121.5766);
    way["highway"](25.0230,121.5528,25.0446,121.5766);
    relation["building"](25.0230,121.5528,25.0446,121.5766););
  out body geom;
  ```
  **驗收**：`district.js` 可讀、座標範圍正確（101 在原點附近）、含 ODbL 出處註記、建物數量與 OSM 網頁目視相符。
- [ ] **T1.2 道路生成器**：`city/roads.js` — 讀 `district.js` 路網，依 class 分寬度與材質（幹道瀝青/巷道水泥）、畫邊線與中央線、幹道中央分隔島；人行道沿路自動生成。**驗收**：忠孝東路五段/信義路五段/基隆路的寬度與走向與地圖一致；飛行視角下路網與 OSM 截圖比對方向正確。
- [ ] **T1.3 通用建築生成器**：`city/blocks.js` — footprint 多邊形 → 擠出量體＋窗帶貼圖（L1/L2 LOD 預留）＋平屋頂；樓高優先用 OSM `height`，缺漏用 `levels × 3.2 m`。**驗收**：信義區全部街廓量體成形，飛行比對天際線輪廓接近實景。
- [ ] **T1.4 城市總管接入**：`city.js` 以 150 m chunk 建構整個信義區（路網＋街廓），玩家出生點設四四南村前。**驗收**：全程漫遊不卡頓（串流預算內），distant chunk 正確休眠。

## 7. 地標施工要點

### 7.1 台北 101（全案難度最高的單體）

**程序**：先收集 3 張以上實景照片 → 依照片量比例定段高 → 參數化建模 → 對輪廓微調。**不要憑記憶寫死尺寸。**

幾何拆解（由下而上，參數初始值、以照片為準修正）：

| 段 | 內容 | 建模方式 |
| --- | --- | --- |
| 裙樓 | 商場量體（含 TIFF 綠建築意象） | Box＋玻璃幕牆貼圖 |
| 塔樓基座 | 收分過渡段 | 擠出梯形 |
| 斗形主體 ×8 | 每段約 8 層樓高、梯形斷面「下寬上窄再外張」，逐段縮小——竹節／斗形是 101 的靈魂 | `LatheGeometry` 或逐段 `CylinderGeometry(4 邊形化)`＋角部裝飾貼圖 |
| 頂部段 ×4 | 圓筒狀收分 | Cylinder 疊段 |
| 塔尖 | 細長收至約 508 m | 圓錐＋細桿 |

材質：藍綠色玻璃幕牆＝程式生成格柵貼圖（窗框深色網格＋淡綠反射漸層）；斗形層角部「如意/銅錢」紋樣以貼圖帶過。夜間：輪廓燈＝沿每段斗形層緣的 emissive 細帶（暖白），接入燈光註冊表；跨年模式由煙火系統接管。

### 7.2 四四南村

低矮連棟平房（單棟約 2 層樓高）＋深灰黑瓦雙坡頂＋灰磚牆＋藍白木窗；保留「望 101 的視線走廊」是硬性要求——**村內草坪朝 101 方向不得放置任何高過屋脊的物件**。

### 7.3 國父紀念館

黃色屋頂（翹簷曲線用自建 profile 的 LatheGeometry 或分段斜板）＋白色本體＋四面迴廊柱列＋正面階梯；中山公園含翠湖水岸。

### 7.4 百貨廣告牆

CanvasTexture 大畫布（2048 寬）畫風格化海報；換檔動畫用 `texture.offset.x` 位移（畫布畫兩三格海報輪播），不重繪 canvas。

## 8. 資料格式規格（`js/data/district.js`）

生成器輸出＝人類可讀可手改。S 級地標標記 `override`，生成器跳過、由 `landmarks/` 接管。

```js
/* 由 tools/build-district.mjs 生成 · 2026-10-19
   底圖 © OpenStreetMap 貢獻者 (ODbL) · 手工校訂請直接改本檔 */
export const meta = {
  originLat: 25.0338, originLon: 121.5647,   // 世界原點（台北101）
  generated: '2026-10-19T12:00:00Z'
};

export const roads = [{
  id: 'w26736417', name: '忠孝東路五段',
  class: 'major',                     // major 幹道 / minor 次要 / lane 巷道
  lanes: 6, oneway: false, busLane: true, elevated: false,
  path: [[x1,z1], [x2,z2], /* ... */] // 世界座標公尺
}, /* ... */];

export const buildings = [{
  id: 'w123456789', name: '',         // 名稱供招牌 POI 用
  tier: 2,                            // 1 核心 / 2 延伸 / 3 背景
  poly: [[x,z], /* ... */],           // footprint 多邊形
  height: 41.6, levels: 13,           // 高度優先於樓層數
  roof: 'flat',                       // flat / gable
  override: null                      // 'taipei101' 等則不走通用生成
}, /* ... */];

export const zones = [{ kind: 'park', poly: [/*...*/] }];   // park / plaza / water

export const pois = [{ kind: 'shop', name: '吳興街早餐店', x, z, facing: 'W' }];
```

手工校訂原則：**座標錯了改資料檔，不要改生成器邏輯**；發現通則性問題（如某類樓高系統性偏低）才改生成器並重跑。

## 9. 常見問題排除

| 症狀 | 原因與解法 |
| --- | --- |
| 開頁全白 | ES modules 必須走 HTTP——確認用 `http://localhost:8642` 而非雙擊檔案；看 Console 是否 module 404 |
| 畫面過曝或全黑 | 踩了 §3.1 encoding 陷阱（新舊 API 混用）；檢查所有 renderer/texture/shader 三處 |
| 合併後幾何貼圖錯亂 | `mergeGeoms` 丟 UV——需貼圖的幾何用 `mergeBufferGeometries`（T0.9）或各自獨立 mesh |
| 陰影閃爍/條紋 | 陰影相機範圍過大或 bias 不當；範圍跟隨玩家、`shadow.bias` 微調 |
| 走動時偶發卡頓 | chunk 建構超過每幀預算——確認佇列限時機制未被繞過 |
| `BufferGeometryUtils` import 失敗 | r149 檔案內部 import 路徑需改為本 repo 的 `../../three.module.js` 相對路徑 |
| 效能面板數字異常 | 以 `renderer.info.reset()` 每幀歸零為前提（EffectComposer 下 draw calls 會乘 pass 數，屬正常） |
